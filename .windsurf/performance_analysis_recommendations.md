# Дополнительные рекомендации по оптимизации производительности (UI Performance)

На основе анализа предложений, кодовой базы и твоих уточнений, я подготовил финальный детализированный план.

## 1. Стратегия обновления БД (Phase 1.1) — "Event-driven + Prefs"
**Рекомендация:** Отказаться от ежесекундной записи в БД в пользу комбинированного метода.

*   **Основное хранилище "live" позиции:** `SharedPreferences`. Записываем туда часто (раз в 1-2 сек), так как это не триггерит UI-обновления через Room Flow.
*   **Синхронизация с БД (Room):** Только в ключевые моменты:
    1.  **Pause / Stop / Seek:** Когда пользователь явно меняет состояние плеера.
    2.  **Next Episode:** В момент перехода на следующий трек (сохраняем финал текущего).
    3.  **Background Backup:** Раз в 30 секунд (на случай краша системы).
*   **Почему это лучше:** Мы полностью убираем "каскад обновлений" (DB -> Flow -> DiffUtil) во время активного воспроизведения. UI будет абсолютно плавным, а позиция всегда сохранена.

## 2. Устранение дублирования циклов опроса (Критично)
В приложении сейчас два "тикающих" механизма:
1. `MediaService.startPeriodicPositionUpdate` (каждые 500мс)
2. `MainViewModel.updateCurrentPlayerPosition` (каждые 500мс)

**Рекомендация:**
*   Удалить цикл из `MainViewModel`.
*   `MainViewModel` должен получать позицию напрямую из `MediaServiceConnection` (через `playbackState`).

## 3. Оптимизация DiffUtil и Adapter (Phase 2)
### AsyncListDiffer и Drag & Drop (Синхронизация)
**Проблема:** Асинхронный расчет разницы может "перебить" локальные изменения при перетаскивании.

**Решение:**
1.  **Флаг блокировки:** Ввести в адаптер флаг `isDragAndDropActive`.
2.  **Заморозка обновлений:** В методе `submitList` игнорировать входящие списки из БД, пока флаг `true`.
3.  **Синхронизация после Drag:** После завершения жеста отправляем новый порядок в БД.

### Игнорирование stopListeningAt в DiffUtil
*   В `EpisodeFeedAdapterV2.areContentsTheSame` **перестать** сравнивать `stopListeningAt` для всех эпизодов. 
*   **Исключение:** Смена состояния с "0" на ">0" (появление иконки прогресса). Микро-изменения секунд в списке не важны.

## 4. Адресные уведомления (Payload Optimization)
**Рекомендация:**
*   Хранить `lastPlayingEpisodeId` в адаптере.
*   При смене трека вызывать `notifyItemChanged` только для ДВУХ позиций (старый и новый трек), а не для всего списка через `notifyItemRangeChanged(0, itemCount)`.

## 5. Оптимизация отрисовки фона (itemsBackgroundFactor)
**Рекомендация:**
*   Использовать `layoutManager` для поиска только видимых айтемов.
*   Обновлять фон только для того, что на экране.
